# Meetings App

List, create, and delete meetings with participants. FastAPI + PostgreSQL backend, React + shadcn/ui frontend, all run with Docker Compose. See [SPEC.md](SPEC.md) for the full specification.

## Quick start

Requires Docker.

```sh
make up      # creates .env from .env.example, builds and starts everything
make seed    # optional: sample participants and meetings
```

- App: http://localhost:3000
- API docs: http://localhost:8000/api/docs

If port 5432 is already in use on your machine, set `DB_PORT` in `.env` (e.g. `DB_PORT=5433`).

## Common commands

Run `make` to list all targets. The most used:

| Command | What it does |
|---|---|
| `make up` / `make down` | Start / stop the stack |
| `make logs s=backend` | Follow logs of one service |
| `make test` | Backend tests (in the backend container, against `<db>_test`) |
| `make lint` / `make format` | Ruff + oxlint/Prettier |
| `make migration m="..."` | Autogenerate an Alembic migration |
| `make psql` | Open a psql shell |
| `make clean` | Stop and delete the database volume |

## Local development without rebuilding images

Requires [uv](https://docs.astral.sh/uv/) and Node.js.

```sh
make install        # uv sync + npm install
make dev-backend    # Postgres in Docker, API on :8000 with reload
make dev-frontend   # Vite on :5173, proxies /api to :8000
```

## Deploy to AWS

Infrastructure is managed using Terraform configurations in [`infra/`](infra/) and deployed to `us-east-1` by default (`AWS_REGION` in `.env`).

- **Authentication & Core Infrastructure** (`auth.tf`, `reports.tf`): Cognito User Pool, Client, Domain, S3 Bucket for reports, and SQS Queue for processing requests.
- **AI Infrastructure** (`ai.tf`): IAM roles and execution policies for AWS Bedrock integration.

### Deployment commands

make tf-init     # Initialize Terraform and download provider plugins
make tf-plan     # Preview infrastructure changes
make tf-apply    # Apply infrastructure changes to AWS / HCP Terraform
make tf-destroy  # Destroy managed infrastructure
make infra-lint  # Validate Terraform files and code formatting

### Custom domain

Once everything is deployed, set the domain in `.env` and attach it:

```sh
DOMAIN_NAME=app.example.com
HOSTED_ZONE_ID=Z0123456789ABC   # optional: only if the domain's DNS is in Route 53
```

```sh
make add-domain
```

This requests an ACM certificate in `us-east-1` (the only region CloudFront accepts), adds the domain to the CloudFront distribution and to the backend's CORS origins. With `HOSTED_ZONE_ID`, the validation and alias records are created in Route 53 for you. Without it, the command prints the validation CNAME to add at your DNS provider, waits for the certificate, and then prints the CNAME that points the domain at CloudFront. Later `make deploy` runs keep the domain. `make remove-domain` detaches it again (to switch domains: `make remove-domain`, change `DOMAIN_NAME`, `make add-domain`).

### Tags

Every AWS resource that supports tags is tagged `PROJECT_NAME=<PROJECT_NAME>` (in the templates as `Key: PROJECT_NAME, Value: !Ref ProjectName`, plus stack tags and tags on the SSM parameter). Find the whole app with Resource Groups & Tag Editor, and split out its costs in Billing once `PROJECT_NAME` is activated as a cost allocation tag. `APP_NAME` in older `.env` files still works as the project name.


## Deploy to Google Cloud (Lab 9)

The core of the app (frontend, API, database) can also run on Google Cloud. Decisions and trade-offs:
[`docs/adr/0008-spry-on-google-cloud.md`](docs/adr/0008-spry-on-google-cloud.md); costs on both clouds:
[`docs/lab9/cost.md`](docs/lab9/cost.md).

| Piece | Google Cloud | Where |
|---|---|---|
| Frontend | Firebase Hosting (rewrites `/api/**` to Cloud Run) | `firebase.json` |
| API | Cloud Run, image without the Lambda adapter | `backend/Dockerfile.cloudrun`, `gcp/main.tf` |
| Database | Cloud SQL for PostgreSQL 17, `db-f1-micro`, 10 GB SSD | `gcp/main.tf` |
| Images | Artifact Registry | `gcp/main.tf` |
| DB password | generated by Terraform, stored in Secret Manager | `gcp/main.tf` |

**Still on AWS:** sign-in (Cognito; the API on Cloud Run keeps verifying Cognito ID tokens), the weekly
report (EventBridge, SQS, S3, SES) and the agenda parser (Bedrock).

### Run it locally the way Cloud Run runs it (no Google account needed)

```sh
docker compose down                                         # the normal stack also uses port 3000
docker compose -f docker-compose.cloudrun.yml up -d --build
```

- Frontend (stand-in for Firebase Hosting): http://localhost:3000
- API (stand-in for Cloud Run, `PORT=8080`): http://localhost:8080/api/health, docs at http://localhost:8080/api/docs
- PostgreSQL (stand-in for Cloud SQL): `localhost:5433`

Sign-in needs the Cognito IDs in `.env` (`COGNITO_USER_POOL_ID`, `COGNITO_CLIENT_ID`, `COGNITO_DOMAIN`).

### Deploy to Google Cloud

Prerequisites: a project (e.g. `spry-<name>-2026`) with billing and a budget alert, the gcloud CLI
signed in with `gcloud auth application-default login` (no service account keys), Terraform, and the Firebase CLI.

```sh
cd gcp
cp terraform.tfvars.example terraform.tfvars    # fill in project_id, Cognito IDs, CORS origins
terraform init
terraform apply -target=google_artifact_registry_repository.backend   # enables APIs, creates the registry

# build and push the API image
gcloud auth configure-docker us-central1-docker.pkg.dev
docker build -f ../backend/Dockerfile.cloudrun -t "$(terraform output -raw image)" ../backend
docker push "$(terraform output -raw image)"

terraform apply                                 # Cloud SQL (~10 min), secret, Cloud Run

# frontend: built with an empty API base, Firebase rewrites /api/** to Cloud Run
cd ../frontend && npm ci && npm run build && cd ..
firebase deploy --only hosting --project <project_id>
```

### Stop the database

Cloud SQL does **not** pause on its own like Aurora: a running `db-f1-micro` costs ~$7.67 a month.

```sh
cd gcp
terraform apply -var db_activation_policy=NEVER    # stop: only storage is billed (~$1.70/month)
terraform apply -var db_activation_policy=ALWAYS   # start again
terraform destroy                                  # remove everything Lab 9 created
```
